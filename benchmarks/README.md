# Benchmarks

## Native REPL source packages

Measure JSONL REPL phases and generated Odin size before and after importing
large Kvist source packages:

```sh
./scripts/bench_repl_source_packages.sh
```

To measure an already-built compiler without rebuilding it:

```sh
KVIST_BENCH_COMPILER=/absolute/path/to/kvist \
  ./scripts/bench_repl_source_packages.sh
```

The report includes a minimal fixed-array expression, initial `kvist:data`
and `kvist:arr` loads, warm composite expressions, and repeated equivalents.
It prints frontend/emission, Odin build, worker load, native execution, total
controller time, generated bytes, and frontend/native cache hits. Timings are
diagnostic rather than pass/fail criteria; regression tests assert structural
source-size reduction and cache reuse.

On 2026-08-28, the same `-o:speed` CLI build configuration on the development
macOS machine produced the following representative JSONL results. `before`
is `9ceeb737`; `after` enables reachable native generations. Times are
individual runs rather than acceptance thresholds.

| request | generated bytes before | generated bytes after | Odin ms before | Odin ms after | total ms before | total ms after |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| load `kvist:data` after a minimal generation | 417,020 | 19,077 | 417 | 245 | 692 | 531 |
| first composite `get` | 415,828 | 15,125 | 546 | 235 | 818 | 523 |
| `data.first` composite | 416,131 | 16,388 | 561 | 236 | 809 | 504 |
| equivalent composite after result-history rotation | 416,110 | 15,125 | 559 | 0 | 814 | 218 |
| first `kvist:arr` fixed-array expression | 68,170 | 5,717 | 238 | 234 | 495 | 466 |

The repeated `Data` composite changes from a miss to a native cache hit because
unreferenced recent-result adapters no longer perturb the generated source.
Worker loading remains a material fixed cost (roughly 125--180 ms on this
machine), and frontend analysis still sees the complete typed package graph;
the optimization primarily removes irrelevant emitted code from Odin parsing,
checking, and code generation.

The benchmark scripts compare generated Kvist programs with direct Odin
implementations of the same work.

```sh
./scripts/bench_sequence_helpers.sh
./scripts/bench_aggregate_helpers.sh
./scripts/bench_mutation_helpers.sh
./scripts/bench_closure_helpers.sh
./scripts/bench_source_backed_arr.sh
./scripts/bench_core_helpers.sh
./scripts/bench_package_helpers.sh
./scripts/bench_data_collections.sh
./scripts/bench_data_messages.sh
```

The sequence and source-backed array scripts accept `BASE_REF` to compare the
current checkout with another Git revision:

```sh
BASE_REF=main ./scripts/bench_sequence_helpers.sh
```

These are regression tools, not general performance claims. Compare equivalent
workloads and inspect generated Odin when a result changes unexpectedly.
